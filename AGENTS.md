## Release workflow

- GitHub source of truth: `yigitefeoktar/Memory-Arena-Survival`, branch `main`. Writable remote in the saved PC checkout: survival (verify its URL; origin in the saved PC checkout points to Memory-Arena). Verify the destination is `https://github.com/yigitefeoktar/Memory-Arena-Survival.git` before pushing; never push another game's code.
- Inspect Git status, preserve unrelated work, stage only task changes, run `npm run lint`, `npm test` and the relevant production build. Report actual failures. Commit authorized code/UI changes to main and push without force-pushing. Read-only work does not authorize releases.
- Frontend target: Vercel project `memory-arena-survival` (`prj_0W2mJ2sohdbT1eRyF8Qwb28e40mH`), team `team_xVwirII3Qvw8wj4rshxpfiL4`. Stable production URL: https://memory-arena-survival.vercel.app/
- GitHub main publishes this project's frontend. Use `npm run build:frontend` (Vite frontend mode) and `dist/frontend`; `vercel.json` declares the static build. Run lint, tests and this frontend build before pushing, then verify Vercel READY and the exact pushed SHA. Do not use the legacy combined/server build for Vercel.
- Frontend mode explicitly disables Socket.IO and ByteBrew configuration requests. Preserve the clean main-menu layout with START RUN and LOAD SAVED RUN. The small arrow inside START RUN opens a compact Normal/Hard selector, with Normal selected by default. Both modes use 100 HP and require two streaks on wave one and three on all later waves; wave two starts with the regular 24-enemy roster. Enemy movement speed does not increase with waves, elapsed time, or player levels. Normal continuously regenerates 2% of maximum HP per second during active play, without a delay after damage; Hard has no in-wave regeneration. Selecting a mode does not start a run; the main START RUN button starts the selected mode. Keep the split button seamless, without a separator or a separate difficulty row. Both parts share the same hover style: the main part highlights the whole button, and the arrow only its own area. New runs use the standard solo arena. Saves and retries retain their difficulty, and both modes fully heal on wave clear. Multiplayer and map selection are hidden. Single-player stays usable without this PC. To enable a backend later, require explicit authorization, a separate backend contract/URL and end-to-end tests before changing these build gates. Never inherit Ricochet's backend.
- Wave one is a short tutorial on every new run/retry, with no pop-ups or forced delays. Start with three red circles near and visible to the player; introduce three blue circles after the first kill. Keep enough matching targets to finish a streak without growing the new tutorial roster beyond six. Keep the existing streak progress and streaks-left HUD counters; do not show the separate tutorial instruction/goal panel below them. Show “Shoot These” tags only over enemies matching the current streak, updating immediately on a different kill and hiding after wave one. Older wave-one saves retain their enemies/progress and receive matching reinforcements when needed; no tutorial completion storage is required.
- Backend: explicitly disabled/deferred (`deployment.json` has `backend: null`). Multiplayer is not working/verified for this game yet. Do not install/update any PC backend, port, Windows task or tunnel. Server files/dependencies are not permission to enable one. Frontend-only games also use a missing/null backend declaration and skip all backend operations.
- In both Normal and Hard, hostile triangles share one attack slot across preparation and charge. Waiting triangles keep wandering; recovery or death frees the slot. Loading older saves normalizes overlapping triangle attacks.
- In both modes, regular enemy movement is 25% slower (33.75–45 px/sec); triangle charges retain 350 px/sec. Save version 23 applies the slower regular speed once when loading older saves. Nearby enemies gently drift apart within 2.5 times their combined radii, capped at 24 px/sec and constrained by arena walls, independently of pursuit direction. Ease inward movement near neighbours so pursuit cannot overwhelm the drift. Preserve the overlap solver; preparation and charging triangles skip decorative separation drift.
- In both modes, player bullets travel at the original constant 120 px/sec from launch, with no initial speed burst and the higher firing rate retained (800 ms initial fire interval). Player shots use their original round cyan appearance with a soft circular glow; enemy bullet speed and appearance stay unchanged. Player shots check their whole flight path to hit the nearest target and stop at intervening walls or shields. Save version 22 migrates older in-flight player bullets, including the 300 and 900 px/sec versions, to the original speed without changing their direction or ability multipliers.
- Solo shots check the entire player-to-muzzle path against arena and build walls before spawning, including each side stream independently. Touching a wall must not let bullets spawn inside or beyond it; firing away from or parallel to a wall remains possible. Solo shots do not inherit the legacy recently-touched build-wall exemption.
- Selecting Hard turns the main menu's orange UI accents red. Hard runs use matching red arena banners and effects; Normal keeps orange. Banner themes follow the run's saved difficulty, including loads and retries.
- Keep the main menu and solo defeat screen responsive across PC, tablet landscape/portrait, and phone portrait (down to 320px wide). Portrait tablets up to 1024px use the centered, wider portrait composition. Keep difficulty options inside the viewport by opening above START RUN when needed, retain safe-area padding and dynamic viewport sizing, and keep Pause/Quit at least 44px high. Detect touch controls from pointer capabilities and touch-capable iPads even when Safari identifies as a Mac; saved runs and retries use the current device's controls.
- Solo defeat uses the selected Arena aftermath game-over screen: dark left column without game branding, a Hard badge only (no Normal label), cream ANNIHILATED title, time survived and highest wave, and stacked RETRY ARENA / MAIN MENU buttons; geometric arena artwork occupies the right. Time survived uses the saved `memoryRunElapsedMs` counter, excludes pauses, and displays MM:SS (H:MM:SS for runs of an hour or more). Normal actions and rules are orange; Hard uses red, while both retain the cream headline. Vertically center the entire results group within the left column, including the Hard badge when present; use equal top and bottom padding and allow scrolling when the content exceeds the screen height. Keep the responsive buttons and staggered entrance. Complete the exit animation before restarting or returning to the menu, reject duplicate clicks during exit, and skip decorative motion and transition delays when reduced motion is requested. Retry retains the run's difficulty.
- Do not start a local development server unless asked. A bounded production smoke test may verify a release. Check the published menu, both solo difficulties, saved-run loading, absence of multiplayer/map controls and console errors. For rollback, promote a verified previous Vercel deployment and reconcile main so the next release retains the fix; keep this stable URL.
- Free services only; no domain purchase. Updates may end multiplayer matches once a backend is explicitly enabled; the user updates when nobody is playing.
